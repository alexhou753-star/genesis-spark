## 1. 目标与边界

### 1.1 "长期不腻"的含义

"长期不腻"在本作里**不是"内容足够多、够玩很久"**，而是：**在每一个重复周期里，玩家仍要面对需要重新判断的取舍**。量化为三个可讨论的概念：

- **决策维度**：一个会改变玩家最优行动的独立选择轴（如"选哪种政体""走哪条统一路线""种什么/邻接什么""把行政算力分给内政还是外交""这一层重置先升什么"）。维度是"结构性选择"，不是"数值大小"。
- **决策新鲜度**：在一个时间窗内，**新引入的决策维度**与**尚未被解掉的决策维度**共同构成的可用取舍空间。
- **浅层重复**：反复执行同一层的同一动作序列（堆同类建筑、刷同一层重置、刷同一订单池）而不进入新维度。
- **占优**：某选项对所有局面都不劣于其它选项（弱占优为"不劣"，严格占优为"严格更优"）；"全局严格占优"=存在一个通吃选项。

**目标方向**（不是硬指标）：让"新决策维度的出现速率"不低于"旧决策维度被解掉/被占优压掉的速率"。这是长线"不腻"的结构性来源，与 PRD 第 2 章差异化主张 2（长期多周目）、设计原则 D1/D5/D6 一脉相承（D1：任何正面成长必须伴随边际成本或排他约束；D5：失败有惩罚但不清档；D6：重置是长线目标不是惩罚）。

### 1.2 边界：明确不承诺什么

1. **2000 小时不是内容量目标。** 本作不靠"首发堆 2000 小时内容"实现长期可玩性；目标是把"决策新鲜度"做成可持续机制，而不是把时长做成线性内容堆砌。
2. **2000 小时不是测试可直接证明的结论。** 无头引擎 + Bot 仿真（NFR-13、AC-10）只能证明"**在给定策略样本集与阈值下，未发现某类结构性退化（无新维度 / 出现全局严格占优 / 浅层不递减 / 自动化可替代战略 / 新周目约束不变 / 存在无风险净正循环）**"。它**不能证明**真人玩 2000 小时不腻——后者牵涉人类心理、社群、Meta、版本内容节奏，超出可自动化验证范围。
3. **不把"不腻"设成发布门槛的因果指标。** 对齐 PRD 第 4 章"指标只表相关性、不作因果"与反向护栏口径：本文件只交付**反向断言/护栏**（一旦发生某类退化即判不通过），不把"不腻"写成"达到 X 即证明不腻"的正向因果承诺。
4. **长期可玩性最终需要真人长测 + 上线后数据观测**（相关性），本文件只负责把"可结构化的那部分"变成可自动验证的约束；不可结构化的部分显式标注为"仅观测/仅真人验证"（见第 5 节）。
5. **本文件不重新定义任何 FR 或数值**；FR 编号引用 PRD，数值引用数值配置表（PRD 附录 C / A-04），一律为占位。

### 1.3 与产品既有口径的衔接

- 反向护栏（PRD 4 章）："单一策略模板使用率超过 70%（说明策略空间被解掉）"——本文件 C2 给它一个离线可测的对应物（样本内无全局占优）。
- 设计原则 D1–D6、商业化原则 12.1（不卖决策/不卖自动化/不卖信息）——本文件 C4 与 C6 是其长期版的结构断言。

## 2. 六条可验收约束

> 写法约定：每条给出**设计要求 → 对应 FR → 可测试的反向断言（可证伪）→ 测试手段（挂在批次 5a/5b）→ 不能证明什么**。反向断言一律写成"**若出现 X 则判不通过**"，以便 Bot/回归直接判定；具体阈值/样本集见 PRD OQ-15（数值评审门禁），本文件不擅自定死数值。

### C1 每次重置新增决策维度

- **设计要求**：每深入一层重置（或每个新周目）必须**新增至少一个不可由旧层维度线性组合得出的决策维度**，而不是把旧层内容按数值放大重复。深度来自"维度"而非"数量"。
- **对应 FR**：FR-08（每纪元"新资源链 + 一条新硬核约束"）、FR-23/FR-24（两层重置）、FR-40（产业沉淀池/协同，P1）、FR-37（奇点坍缩/升维协议，P1）、FR-45（属目×特质，P2）。
- **可测试的反向断言**：设第 L 层的"可用决策维度集合"为 D_L。**若存在某相邻层对 (L, L+1) 使 |D_{L+1} \ D_L| = 0（仅数值放大、无新维度），判 C1 不通过。** 强化版：断言 |D_{L+1} \ D_L| ≥ 1，且每个新周目可表达的操作集合不是上一周目的子集。
- **测试手段**：sim-cli 枚举每层/每周目可表达的命令与配置维度（命令类型 + 影响最优解的约束参数），做层间差集统计。
- **不能证明什么**：不能证明新维度对玩家"主观新鲜"；不能证明维度总量足以撑 2000 小时；只证明**结构上确有新增维度**。

### C2 无全局严格占优

- **设计要求**：任一"主策略轴"（政体、统一路线、种族、宇宙、星级、重置层选择）都不存在对所有局面都最优的单一选项；优势必须依赖局面与代价条件（"各选项各有优势区间"）。
- **对应 FR**：FR-14（政体 ≥2 强正面/≥2 强负面、数值回归证明无严格占优）、FR-51（三路线"各优势区间"、非"全局无占优"）、FR-25（星级）、FR-26（宇宙）、FR-23/FR-24（交替浅深优于只刷浅层）。
- **可测试的反向断言**：对每个主策略轴，在策略样本集上，**若存在某选项 S\* 对 ≥X% 的局面同时满足"收益不低于其它选项且代价不高于其它选项"（即弱占优被广泛实现），判 C2 不通过。** 等价正向表述：断言"至少存在两个选项，各自在某个可行局面子集上严格优于其它选项"（存在优势区间）。
- **测试手段**：Bot 策略对比矩阵（每轴跑对立策略组合），统计各选项胜出的局面分布；阈值 X 与样本集由 OQ-15 定义。
- **不能证明什么**：不能证明人类不会收敛到单一"元策略"；仿真策略集有限，**只能否定"已测样本内的全局占优"，不能证明"不存在任何占优"**。

### C3 浅层重复收益递减

- **设计要求**：反复执行同一浅层动作（刷同一层重置、堆同类建筑、刷同一订单）必须边际收益递减；深处/换维度路径的总效率必须高于纯浅层堆叠。
- **对应 FR**：FR-23（质粒软上限 B(P) 对数衰减）、FR-24（噬菌体衰减且不破硬下限）、FR-05（成本蠕变严格递增、硬下限 1.015）、FR-04（每纪元仓储天花板）、FR-17（订单奖励每日上限）。
- **可测试的反向断言**：**若"连续 N 次纯浅层重置的总加成 ≥ 一次深层/换维路径的加成"（N 取评审阈值，初值建议 10），判 C3 不通过。** 结构性质断言：软上限函数 B(P) 过 knee 后边际收益严格递减（FR-23 已有性质测试口径），且"第 k 次浅层重置的边际增量"随 k 单调下降并趋于 0。
- **测试手段**：批量仿真"只刷浅层"vs"交替浅深"两条曲线对比；对软上限做 property test（单调、knee 处连续、knee 后边际递减）。
- **不能证明什么**：不能证明递减"足够让玩家不腻"；阈值与曲线是数值假设，需真人校准；只证明**数学上浅层不划算**。

### C4 自动化不代替战略选择

- **设计要求**：自动化（内政总管、排程队列、自动补种、自动建造）只降低操作频率，只能在玩家预设规则/优先级内执行，**绝不改变战略目标或替玩家做取舍**；且自动化能力受稀缺约束（行政算力 / 渐进解锁）而非无限。
- **对应 FR**：FR-18、FR-19、FR-48、行政算力三消费者（FR-18/19/51 共用 `AdminPowerConfig`）、设计原则 D1 与商业化原则 12.1（不卖自动化）。
- **可测试的反向断言**：**若存在一条固定自动化配置，使得"玩家除初始一次配置外不做任何战略决策"的长期结果 ≥ 一个持续手动做战略决策的对照玩家结果的 Y%，判 C4 不通过（即自动化不可替代战略）。** 强化断言：**进入下一层/新周目时，此前自动化配置在新约束下必须失效或需人工重设**（即自动化不能自动适应新维度）；且自动化收益上界随规模收敛（受行政算力）。
- **测试手段**：Bot 对照（"设好就不管"vs"每回合手动最优"），差距应显著且随层数扩大；检查进入新层后旧配置的有效性下降幅度。
- **不能证明什么**：不能证明自动化手感好；"策略 vs 不策略"的阈值 Y 由评审设定；只证明**结构上自动化不可替代战略**。

### C5 新周目改变约束条件

- **设计要求**：每次开新周目（重置 / 新星球 / 新宇宙 / 新种族 / 新挑战基因）时，**基础约束条件必须改变**（宇宙修饰、种族规则替换、挑战基因、播种星球生成），使上一周目的最优解不能直接复用，迫使重新规划。
- **对应 FR**：FR-26（重引力/微观规则不同）、FR-07（种族规则替换而非数值皮肤）、FR-25（星级）、FR-46（播种星球生成，P2）、OQ-08/挑战基因（P2）、FR-39（自定义枷锁组合，P1）。
- **可测试的反向断言**：**若存在"同一套开局操作序列在 ≥K 个不同周目配置（宇宙×种族×星级×星球）下都能通关且相对最优"，判 C5 不通过（即约束改变未真正改变最优解）。** 等价表述：断言每对周目配置 (A,B) 的"最优开局序列集合"交集为空或显著缩小。
- **测试手段**：Bot 用固定模板策略跨周目配置跑，统计"同一模板的成功率/是否仍最优"；周目配置两两比较最优策略差异。
- **不能证明什么**：不能证明玩家"每个周目都感到新鲜"；只证明**约束差异足以改变最优解（结构性）**；且当前只覆盖已实现配置（宇宙/种族/星级），**播种星球与挑战基因未实现前无法验证**。

### C6 推进始终有真实风险与恢复成本

- **设计要求**：任何推进（扩张、攀科技、扩自动化、深入重置）都伴随真实且可恢复的风险与成本（断链、污染、失败梯度、上限、蠕变、伤亡）；**不存在"零风险无限推进"的无风险净正循环**；失败有惩罚但不清档（可恢复），且**恢复需要付出代价**（时间/资源/进度折价）。
- **对应 FR**：FR-04/05/06（上限/蠕变/断链）、FR-11（污染）、FR-22（失败梯度 L1–L4 可恢复、不清档、L4 按 60% 结算）、FR-13（母星折叠不可逆）、FR-51（伤亡不死局）。
- **可测试的反向断言**：**若存在一条循环操作序列，使"资源/进度净增长 ≥ 0 且期间任何风险指标（断链/污染/失败 tier/伤亡）始终为 0 或无需付出恢复成本"，判 C6 不通过（发现无风险净正循环）。** 补充断言：失败后**恢复路径的成本 > 0**（恢复需非零时间/资源，对齐 FR-22"可恢复"但"不白费"的 D5 口径）。
- **测试手段**：随机/贪心/搜索 Bot 在状态空间内找"安全套利循环"；失败状态遍历断言"至少一条可执行恢复命令且恢复成本 > 0"（在 FR-22 无死局遍历基础上加"成本 > 0"）。
- **不能证明什么**：不能证明风险"足够刺激"或惩罚"刚好"；大型状态空间下**只能证伪已发现的无风险循环，不能证明绝对不存在**；只证明"未发现零风险净正循环且恢复非免费"。

### 3.3 还缺（长期可玩性专用缺口）

1. **重置层数扩展未建模。** V1.0 只做两层（灰烬 ash、播种 seed）；奇点坍缩、升维协议（FR-37）为 P1/V1.2。`PermaState.resetCounts` 只有 ash/seed 两键（见第 4 节），无法承载"多层维度递增"。
2. **重置层机制差异未定义。** 目前 ash 与 seed 的差异主要是"软上限/噬菌体耦合"数值层，缺少**结构性差异**（不同层要求不同的战略维度）。这正是 C1 的核心缺口。
3. **属目 × 特质（FR-45）未系统化。** 现在是"整只种族"配置（`RaceConfig`），没有 `属目 + 特质` 组合系统；这限制了 C5"新周目改变约束"的可组合空间与 FR-41 的 40+ 种族扩展。
4. **挑战基因完整系统缺失。** `ChallengeGeneConfig{id,multiplier}` 只有单一倍率占位，**没有任何预设组合、互斥、生效规则**；OQ-08 未定。C5（新周目约束改变）目前主要靠宇宙/种族，挑战基因维度无法验证。
5. **跨周目"最优解不可复用"无断言。** 文档没有"同一开局模板跨周目是否仍最优"的检查项（C5 的可测化缺失）。
6. **无风险净正循环检查（C6）缺失。** 现有关卡（Gate 1–6）没有"搜索零风险套利循环"的检查项。
7. **"每层新增维度差集"（C1）缺失。** 无自动化维度枚举/差集。
8. **自动化是否可替代战略（C4）无 Bot 对照。** 文档只有"不替玩家改变战略目标"的原则性回归，没有"设好就不管 vs 持续手动"的量化对照。
9. **节奏（pacing）配置缺失。** 没有为"长期仿真"准备的、可配置的推进节奏（阶段时长/产出曲线/解锁时点），GDD 第 2 节仅有人工占位表。

> **审计小结**：可玩性六条约束里，**C3（浅层递减）与 C6（失败可恢复）在文档/类型层最扎实**（软上限性质、失败梯度结构已在）；**C2（无占优）在政体轴有结构强制但无"无占优"证明**；**C1/C4/C5 是主要缺口**（重置多层维度差异、自动化战略对照、挑战基因/属目特质）。所有这些都**只有类型/口径，没有引擎实现**，离"可测"还差批次 5 的 sim-cli 闭环。

## 4. 最小类型改动建议（只读评估，不落代码）

> 本节只给**评估结论与建议**，不修改任何 `types.ts`。改动以架构师评审为准；任何动到状态结构（进入存档/规范哈希）的改动都要按模块完成定义第 4 条"升 schemaVersion + 写迁移"处理（模块地图）。

### 4.1 核心问题一：`PermaState.resetCounts` 是否改为配置驱动的 `ResetLayerId` 记录？

**现状**（`engine/types.ts` `PermaState`）：

```ts
resetCounts: Record<'ash' | 'seed', number>;   // 键硬编码为 'ash' | 'seed'
```

**问题**：`resetCounts` 是**永久成长状态**（跨周目，进入存档与规范状态哈希），其键被写死为两层。一旦 V1.2 增加奇点坍缩（FR-37）/升维协议，就要**改存档结构 + 写迁移 + 改所有读它的代码**；且与 A2/FR-48 的解锁条件 `UnlockCondition.resetLayer: { kind:'resetLayer'; layer:'ash'|'seed'; times }` 的 `layer` 也硬编码为 `'ash'|'seed'`（`configs/types.ts`）互相绑死。这与"长期可玩性=多层重置新增维度（C1）"直接冲突——**无法在不改类型的前提下扩展重置层数**。

**建议（评审用，二选一）**：

- **方案 A（推荐，最小且面向未来）**：引入配置驱动的 `ResetLayerId = Id`（放在 `configs/types.ts`，因层清单属配置），把
  - `PermaState.resetCounts` 改为 `Record<ResetLayerId, number>`（或更稳妥：`Partial<Record<ResetLayerId, number>>`，缺键视为 0，**避免旧存档缺新键时的迁移负担**）；
  - `UnlockCondition.resetLayer.layer` 改为 `ResetLayerId`。
  - 由 `GameConfig` 新增可选 `resetLayers?: ResetLayerConfig[]`（`{ id: ResetLayerId; index: number; ... }`）作为层清单真源，Gate 1 校验 `resetCounts`/`UnlockCondition` 里出现的 layer 必须存在于层清单。
- **方案 B（过渡）**：暂保留 `'ash'|'seed'` 字面量联合，但**在键类型上预留扩展位**（如 `type ResetLayerId = 'ash' | 'seed' | (string & {})` 的开放联合）；**不建议**，因为它只是掩盖问题、且丢失 Gate 1 的引用完整性校验。

**推荐落点**：**方案 A**。理由：① `resetCounts` 属 perma，进存档，**改类型时机越早越省迁移**（模块地图 B 表"星级、宇宙进入存档"同样是"内测存档出现前改只是改类型，之后每改要写迁移"的判断口径）；② 它把"重置层清单"变成配置真源，直接服务 C1（多层新增维度）与 C3（多层浅深对比）的可持续扩展；③ 用 `Partial` 语义可让旧存档（只有 ash/seed）零迁移兼容。

**风险与代价**：`resetCounts` 在规范状态哈希覆盖范围内（`CanonicalHashInput.perma`），改类型后**规范哈希会变**——但当前**尚无内测存档**（README 明示未实现存档编解码），此刻改是"零迁移成本窗口"。建议在 batch 5 之前定，避免进入有存档阶段后再改。

### 4.2 核心问题二：`UnlockCondition.resetLayer` 是否需要扩展？

**现状**：`{ kind:'resetLayer'; layer:'ash'|'seed'; times:number }`。

**评估**：与 4.1 同源。若 4.1 采用方案 A（`ResetLayerId`），则此处 `layer` 同步改为 `ResetLayerId` 即可，**语义不变、结构不变**（仅键类型放宽）。**不需要**新增字段（不需要 `>= / > / 累计口径` 等），因为现有 `times` 语义是"累计执行次数达到 times"，已足够表达 FR-48 的渐进解锁。

**建议**：**跟随 4.1，把 `layer` 放宽到 `ResetLayerId`；其余不动。** 若暂不采纳 4.1，则此字段**保持不变**，等层扩展时一起改（但要接受届时两处一起迁移）。

### 4.3 核心问题三：如何为"长期仿真"准备节奏配置？

**判断**：长期可玩性的 Bot 仿真（第 5 节）需要**参数化的推进节奏**（阶段时长、每层目标进度区间、产出曲线形状、软上限 knee、行政算力曲线、解锁时点），但**当前没有这样的配置顶点**：GDD 第 2 节的自动化节奏是"人工占位表"，`GameConfig` 里没有统一的 pacing 段。

**建议（分两步，均"可选字段优先"，避免破坏现有配置）**：

1. **第一步（现在可加，低风险）**：在 `configs/types.ts` 增设**可选** `GameConfig.pacing?: PacingConfig`，只承载"仿真可读"的**节奏参数**（如每层目标单周目游戏时长区间 `targetRunHours`、软上限 knee 引用、解锁时点表、难度曲线档位）。全部 `?` 可选、缺省时引擎按内置默认处理——与现有 `automation?`、`plasmidSoftCap?` 一致的口径，**不动任何既有必填结构**。
2. **第二步（batch 5 之后，按需）**：把 `AutomationUnlockConfig` 的占位节奏（GDD 第 2 节表）真正写入配置（`automation` 已有字段，只是缺数值），不需要新类型。

**明确**：节奏配置是**仿真与数值调参的载体**，不引入"运行时按节奏改变规则"的机制；它只让 Bot 能按同一套参数跑不同层/不同周目。**不改变玩法结算语义**。

## 5. 批次 5a/5b 的验收方向

> 前提：`src/engine` 目前只有类型、无引擎实现（README 明示）。批次 5 是在把引擎骨架（事件跳跃、dispatch、离线入口、sim-cli）做出来之后，才谈得上"长期可玩性可测"。本章给出**方向与判据形态**，不写实现、不写死阈值（阈值随 OQ-15）。

### 5.1 批次 5a（基础设施闭环：让"可复现 + 可批量"成立）

| 目标 | 验收方向 | 对应约束 |
| --- | --- | --- |
| **sim-cli 闭环** | 无头引擎可在 Node 中加载配置、跑完整周目、输出规范状态哈希与关键事件流；同一命令序列在 100/250/1000 ms 步长下资源/事件一致（FR-01/06 口径） | 全部（基础） |

| **跨周目最优解复用检查** | 同一开局模板在 ≥K 个周目配置仍最优 → 失败 | C5 | 模板 Bot 跨配置 |

### 5.3 明确不声称什么（批次 5 的边界）

1. **不声称测试能证明"不腻"。** 5b 的所有通过项只说明"**在给定样本集与阈值下未发现六类结构性退化**"，是对"退化"的**证伪**，不是对"长期不腻"的**证明**。
2. **不把 5b 结果写成发布硬门槛的因果依据。** 对齐 PRD 4 章与 FR-48 验收"自动化使用率/留存只作相关性、不作发布硬指标"的口径：5b 是**结构护栏（阻断明显退化）**，不是"通过即保证高留存"。
3. **样本集有限性。** Bot 策略集与局面样本有限，"未发现占优/未发现无风险循环"≠"不存在"；阈值一旦放宽，结论随之变化——阈值必须在 OQ-15 明确并留档。
4. **真人维度不可替代。** 决策新鲜度是否被玩家"感到"，仍需真人长测与上线后观测（相关性），5b 无法覆盖。

## 7. 关于"不把长期不腻承诺为可测结论"的说明

> 这一节是本文件的**自我约束**，也是回应任务要求"不把长期不腻承诺为可测结论"的正式声明。

1. **"长期不腻"是体验目标，不是可判定命题。** 它依赖真人心理、社群生态、内容更新节奏、Meta 演化，任何单元测试、Bot 仿真、回归都无法对其下"真/假"判断。本文件把其中**可结构化、可证伪**的部分抽出来做成六条反向断言（C1–C6），其余显式排除。
2. **我们只证明"没有明显退化"，不证明"足够好玩/足够耐玩"。** 六条约束全部写成"**若出现 X 则判不通过**"的**证伪**形式；通过 = "未发现该退化类"，不是"证明了不腻"。**"未发现" ≠ "不存在"**，受样本集与阈值限制（第 5.3 节）。
3. **2000 小时不是承诺，是方向。** 本文件不把"2000 小时"写成任何验收门槛、内容量 KPI 或因果指标；它是"决策新鲜度可持续"的一个**愿景锚点**。真正落地靠：多层新增维度（C1）+ 无占优（C2）+ 浅层递减（C3）+ 自动化不替代战略（C4）+ 新周目改约束（C5）+ 有风险有恢复成本（C6）这六个**结构性条件**共同成立，而非任何单一数值。
4. **发布与判断口径对齐 PRD。** 长期可玩性的最终判断交给：真人长测、上线后数据（相关性观测，不作因果）、以及第 4 章反向护栏（如"单一策略模板使用率 >70%"）。本文件不新增因果型发布门槛。
5. **本文件不修改任何 `types.ts` 或测试，不产生任何"已证明"的结论。** 它只是一份**约束草稿**：供架构师评估第 4 节类型建议、供 QA/数值在批次 5 把 C1–C6 落成可跑检查、供策划在 OQ-08/OQ-15 等定稿前知道"哪些维度还缺"。
